# 数字广告责任链与发布门禁

记录合成广告的参与方、素材来源、审查结论和渠道发布责任。

## 参与方与事实

主要参与方包括广告主、内容制作机构、平台审核人员、渠道运营人员，以及只读的审计人员。领域资料记录以下事实：

- 数字人广告可能伪造亲身体验
- 药品和医疗器械宣传需要更严格的责任核验
- 违规内容的责任要穿透制作、发布和销售链条

## 业务边界

- 素材版本
- 身份授权
- 产品资质
- 发布审批
- 责任追溯

当前资料按以下边界组织：

- 广告项目谱系
- 责任主体关联
- 多级审批
- 渠道发布冻结
- 审计重放

`contracts/context.schema.json` 描述资料结构，`fixtures/context.json` 提供不含真实身份信息的示例，`src/campaign_context.py` 负责读取和校验资料。

## 责任链服务

`src/` 在领域资料之上实现了责任链与发布门禁的核心逻辑（无外部依赖，仅标准库）：

| 模块 | 职责 |
| --- | --- |
| `roles.py` | 角色与信息访问边界：广告主、制作机构、平台审核、渠道运营、审计 |
| `events.py` | 只追加事件与 JSONL 存储，支持按历史时点/序号重放 |
| `state.py` | 事件投影：素材谱系、结论、复核、发布、冻结、通知的当前状态 |
| `policy.py` | 发布门禁：资质、身份授权、可证明事实、同人复核等核查结论 |
| `service.py` | 应用服务：立项、提交、增量结论、复核、放行、发布、冻结、期限恢复、审计重放 |

关键保证（详见 `docs/domain-rules.md`）：

- 从立项起保存资质、脚本、数字人、衍生版本、审核意见、购买流量与发布渠道，每版记录提交者/复核者/真实性责任人；
- 医疗内容先核对身份授权与可证明商品事实，审核中的素材渠道无法直接发布；
- 修改脚本或更换数字人只重算受影响的结论（依赖基 + 父版本继承），已放行版本固化当时证据；
- 角色只能访问职责内信息，提交者不得批准自己的内容；
- 渠道回调按 `callback_id` 幂等，重复回调不重复生成发布记录；
- 投诉/撤回/监管调查冻结对应素材谱系（含衍生后代），报告仍在传播渠道、待补材料与责任缺口；
- 审批与通知使用绝对期限，服务重启后按原期限继续；审计可按历史时点重现放行决定。

`tests/test_accountability_service.py` 以端到端用例覆盖上述全部保证。

## 开发命令

运行测试：

```bash
python3 -m unittest discover -s tests -v
```

编译检查：

```bash
python3 -m compileall -q src
```

命令只读取仓库内文件，不需要连接外部业务系统。
