# 数字广告责任链与发布门禁

记录合成广告的参与方、素材来源、审查结论和渠道发布责任，
让广告主、制作机构、数字人供应商、平台审核与渠道代运营对同一份发布前记录负责。

## 解决什么问题

广告下架后才发现：脚本由外包撰写、数字人由另一家公司生成、投放账户由渠道商代运营，
任何一方都拿不出同一份发布前审核记录。本服务从项目立项开始保存完整责任链，
并在发布前设置可审计的门禁。

## 参与方与事实

主要参与方包括广告主、内容制作机构、平台审核人员、渠道运营人员，以及只读的审计与监管。
领域资料记录以下事实：

- 数字人广告可能伪造亲身体验
- 药品和医疗器械宣传需要更严格的责任核验
- 违规内容的责任要穿透制作、发布和销售链条

## 业务边界

- 素材版本与衍生谱系
- 数字人身份授权
- 产品资质与可证明商品事实
- 医疗内容前置核验
- 多级审批与职责分离
- 流量购买与渠道发布门禁
- 投诉/撤回/调查的谱系冻结与责任缺口报告
- 重启后续期审批、按历史时点重放放行决定

## 仓库结构

- `contracts/context.schema.json`：领域上下文结构
- `fixtures/context.json`：领域上下文示例（不含真实身份信息）
- `fixtures/scenario-events.json`：从立项、医疗核验、复核、放行、发布到投诉冻结的完整事件流
- `src/campaign_context.py`：读取和校验领域资料
- `src/responsibility_chain.py`：责任链领域服务（命令、投影、门禁、冻结、重放）
- `docs/domain-rules.md`：完整业务规则
- `tests/`：领域资料校验与责任链服务测试

## 设计要点

- **事件溯源**：所有事实写成只增事件，哈希链防篡改；当前状态由事件流折叠得到。
- **责任明确**：每个素材版本记录提交人、复核人、内容真实性责任人。
- **医疗前置门禁**：医疗内容必须先核对身份授权与可证明商品事实，否则不能复核通过或放行。
- **发布门禁**：审核中的素材渠道不能直接发布；拒绝也留痕；发布回调幂等去重。
- **职责隔离**：角色视图按信息域过滤；提交者不得批准自己的内容。
- **增量结论**：修改脚本或更换数字人只标记受影响的下游版本；已上线版本保留当时证据与责任。
- **冻结报告**：冻结波及的全部衍生版本，给出仍在传播渠道、待补材料与责任缺口。
- **重启续期**：未完成审批与通知按原期限继续，超期放行被拒绝。
- **历史重放**：审计可按事件序号/历史时点重现一次放行决定及其全部门禁依据。

### 快速示例

```python
from datetime import datetime
from src.responsibility_chain import ResponsibilityChainService, Role

svc = ResponsibilityChainService(clock=lambda: datetime(2026, 9, 1, 9, 0))
# 立项 → 资质 → 数字人身份 → 素材 → 版本提交 → 医疗两项前置核验
# → 平台复核（不得是提交者）→ 放行决定 → 广告主购买流量 → 渠道发布
# 投诉/调查 → freeze_lineage() → freeze_report()
# 重启：ResponsibilityChainService.load(path) → pending_on_restart()
# 审计：replay_release_at(version_id, at_time="2026-09-01T12:00:00")
```
