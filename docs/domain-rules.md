# 领域规则

记录合成广告的参与方、素材来源、审查结论和渠道发布责任。

资料版本只能递增，参与方、事实和约束均不能为空。

## 参与方与职责边界

| 角色 | 可处理的信息域 | 可执行的命令 |
| --- | --- | --- |
| 广告主 | 项目、资质、素材、审核结论、流量、发布、冻结、责任缺口 | 立项、登记资质、指定内容真实性责任人、购买流量、投诉/撤回 |
| 内容制作机构 | 项目、素材、审核意见 | 建档、提交脚本/数字人/素材版本 |
| 平台审核 | 项目、资质、素材、数字人身份、审核意见、发布 | 医疗前置核验、出具复核意见、放行 |
| 渠道运营 | 项目、素材版本头、流量、发布、冻结状态 | 渠道准备、发布已放行版本 |
| 审计人员 | 全部信息域（只读） | 冻结、调查、历史重放 |
| 监管人员 | 全部信息域（只读，无审计重放域） | 调查、冻结 |

角色只能看到 `SCOPES` 授权范围内的信息域（`view_as` 投影），越权命令一律拒绝。

## 责任链事实（只增事件）

从立项起，以下事实全部进入哈希链事件流，任何一方都能出示同一份记录：

- 产品资质（注册备案、有效期、可证明的商品事实清单）
- 数字人身份（生成公司、真实自然人、肖像/声音/名义授权及有效期）
- 素材与版本谱系（脚本、成片、衍生版本、`parent_version` 与 `derived_from`）
- 审核意见（医疗身份核验、商品事实核验、发布前复核）
- 放行决定（决定号、批准人、所依据的事件序号）
- 流量购买与实际发布渠道（订单、渠道、发布回调）

每个版本必须明确：**谁提交**（`submitted_by`）、**谁复核**（`reviewed_by`）、
**谁承担内容真实性责任**（`truth_owner`，默认广告主）。

事件只增不改；每个事件携带前一事件哈希，加载时重算校验，篡改即断裂。

## 医疗内容前置门禁

药品、医疗器械、医疗服务内容在发布前复核之前，必须先完成：

1. **身份授权核验**：数字人对应的真实自然人授权在有效期内，证据归档；
2. **可证明商品事实核对**：脚本宣称逐条比对资质中的 `proven_facts`，
   存在无法证明的宣称时不得核验通过。

两项任一缺失：复核不能批准、不能放行、不能购买流量、不能发布。

## 发布门禁

- 审核中的素材（无放行决定）渠道一律不能发布；拒绝发布也写 `PublishRejected` 留痕。
- 提交者不得批准自己提交的内容（职责分离），批准人与提交人必须不同。
- 复核通过后仍须出具独立放行决定；复核驳回/要求修改即关闭审批。
- 渠道重复回调按幂等键去重，重复回调不重复生成发布记录。
- 未放行版本不得购买流量。

## 增量结论与历史保留

- 修改脚本或更换数字人时，只沿版本谱系向下游标记受影响版本
  （`affected_versions_on_change`），失效结论按需重新核验。
- 已经上线的版本不被重写：旧版本标记 `superseded_at`，但当时的证据、
  复核意见、放行决定和责任人永久保留。

## 冻结与调查

投诉、撤回、监管调查可触发谱系冻结：

- 冻结范围从涉及版本沿 `parent_version`/`derived_from` 向上找根、向下收齐整棵子树；
- 冻结后相关素材禁止任何变更与继续发布，并关闭其待办审批；
- 冻结报告给出：仍在传播的渠道（`still_propagating`）、
  待补材料（`pending_materials`）、责任缺口（`responsibility_gaps`，
  含无复核人、无真实性责任人、无放行却存在发布记录等）。

## 期限与重启

- 版本提交即打开带期限的待办：医疗前置核验默认 48 小时，发布前复核默认 72 小时。
- 服务重启后从事件流重放，待办保留**原定期限**；超期放行被拒绝，须重新发起审批。

## 历史重放

审计人员可按事件序号或历史时点重放某次放行决定（`replay_release_at`）：
重现当时的谱系、证据、核验结论与门禁检查项（含「提交与复核分离」），
不依赖任何当前状态。
