# 领域规则

记录合成广告的参与方、素材来源、审查结论和渠道发布责任。

资料版本只能递增，参与方、事实和约束均不能为空。

## 责任链范围

从项目立项开始，以下事实都以只追加事件留痕，并可归属于具体参与方：

- 产品资质（每项事实须附证明材料引用与证据指纹）
- 脚本版本（含宣称的商品事实清单、父版本、提交者）
- 数字人身份（身份主体、生成方、授权文件与有效期）
- 素材衍生版本（脚本/数字人组合、父版本、提交者）
- 审核意见（按脚本版本/数字人版本覆盖，复核者与角色留痕）
- 内容真实性责任声明（广告主声明具体责任人）
- 购买流量与实际发布渠道（渠道、运营人、回调编号、状态）
- 放行决定与放行时刻的证据快照

每个素材版本都明确记录：谁提交、谁复核、谁承担内容真实性责任。

## 发布门禁

渠道只能登记**已放行**素材的发布；审核中的素材一律拒绝。放行必须同时满足：

1. 产品资质结论通过：事实均有证明材料；
2. 可证明商品事实结论通过：脚本宣称的每一项事实都能在资质中找到支撑；
3. 医疗相关内容（或任何使用数字人的内容）额外要求：
   - 数字人身份主体与授权文件齐备；
   - 授权在放行时刻仍在有效期内（结论沿用时也会在放行时刻重新校验）；
4. 对应组件版本有平台审核人员的批准意见；
5. 已声明内容真实性责任人。

## 职责分离

- 提交者不得批准自己提交的内容（命令层按角色分离，门禁层再做同人校验）。
- 放行只能由平台审核人员作出；产品资质与真实性责任只能由广告主登记/声明；
  脚本、数字人与素材衍生只能由制作机构产生；发布与流量只能由渠道运营操作。
- 各角色只能访问职责内信息域（见 `src/roles.py`），越权访问直接拒绝。
- 审计人员只读，并独占审计重放能力。

## 增量结论与历史固化

- 每条核查结论带**依赖基**：资质结论依赖资质登记序号，身份授权结论依赖数字人版本，
  商品事实结论依赖脚本指纹与资质序号。
- 衍生版本只重算依赖基变化的结论；依赖基未变的结论自父版本**继承**，
  事件中记录来源版本与来源结论序号。改脚本不重算身份授权，换数字人不重算商品事实。
- 放行事件固化当时的证据快照；后续修改脚本、更换数字人只产生新版本，
  已上线版本仍保留放行时的证据、结论与责任归属。

## 冻结与责任报告

发生投诉、撤回或监管调查时可冻结素材谱系：

- 投诉、撤回由广告主发起；监管调查由平台审核发起；
- 可指定冻结根版本，冻结范围沿父版本链接覆盖全部衍生后代；
- 冻结范围内禁止新衍生、放行、发布与购买流量（渠道下架/撤回回调仍可送达）；
- 冻结报告给出：仍在传播的渠道、各版本待补材料清单、责任缺口（如未声明真实性责任人）。

## 幂等回调

渠道发布登记与状态回调以 `callback_id` 幂等：同一回调重复投递只返回首次结果，
绝不追加第二条事件或重复生成发布记录。

## 重启恢复与审计重放

- 全部状态由事件投影得到，服务重启重放 JSONL 即恢复。
- 审批与通知的期限在事件产生时记录为**绝对时间**，重启后按原期限继续，
  时钟推进后即可识别逾期审批与未送达通知。
- 审计人员可指定历史时点，仅使用该时点之前的事件重现一次放行决定，
  并比对当时证据指纹与当前记录是否一致。
